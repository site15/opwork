# ТЗ для Lovable: дизайн-макет OpWork с нуля

## 1) Цель

Нужно сгенерировать **полный UI-макет продукта OpWork** (веб) на основе этого документа.
Макет должен покрыть:
- публичный лендинг;
- авторизацию/регистрацию;
- пользовательские кабинеты для двух ролей: **соискатель** и **компания**;
- все ключевые сценарии из продукта поиска работы;
- адаптивные версии (desktop + mobile).

Фокус: **минимализм, читаемость, ясные пользовательские потоки, высокая скорость восприятия**.

---

## 2) Базовые принципы дизайна

1. Визуальный стиль: современный минимализм, аккуратные отступы, много воздуха, без перегруженности.
2. Mobile-first адаптив: сначала логика мобильного опыта, затем расширение до desktop.
3. Единый дизайн-системный подход: токены, типографика, цвета, состояния, компоненты.
4. Контраст и доступность: не ниже AA по контрасту для ключевого текста/кнопок.
5. Сценарный UX: каждый экран отвечает на вопрос "что делать дальше".
6. Пустые состояния: не просто "нет данных", а CTA и пояснение следующего шага.
7. Формы: понятные подписи, подсказки, обязательные поля, inline-ошибки.
8. Таблицы и списки: в приоритете сканируемость (статусы, ключевые метрики, быстрые действия).

---

## 3) Роли и ограничения

### Роли
- Соискатель
- Компания

### Важно
- Роль `ADMIN` в интерфейсе полностью скрыта.
- Активный профиль переключается через хедер и влияет на данные/нотификации.
- Скрытые сущности должны быть недоступны для других пользователей везде:
  - резюме соискателя при `isOpenToWork = false`;
  - вакансия при статусе не `ACTIVE`.

## 4) Информационная архитектура (sitemap)

## Публичная зона
- Лендинг
- Вход
- Регистрация

## Приватная зона (общая основа)
- Хедер: глобальный поиск, нотификации, переключение активного профиля, пользовательское меню

- Мои заявки (`/vacancy/applications`)

- Профиль соискателя (`/profile/specialist`)

- Переписка (чат соискатель <-> компания)
- Приглашения от компании
- Дашборд для обеих ролей

## 5) Ключевые пользовательские потоки

### 5.1 Вход/регистрация
- Вход: `/auth/login`
- Регистрация: `/auth/register`
- После входа редирект по состоянию профиля.

### 5.2 Редиректы после входа

Для компании:
1. Нет заполненного профиля -> `Моя компания`
2. Профиль заполнен, вакансий нет -> `Создание вакансии`
3. Профиль заполнен, вакансии есть -> `Мои вакансии`

Для соискателя:
1. Профиль не заполнен -> `Профиль соискателя`
2. Профиль заполнен, резюме не заполнено -> `Мое резюме`
3. Резюме заполнено -> `Мои отклики`

## 6) Данные и поля (на основе БД)

Ниже поля, которые должны быть учтены в макетах форм и карточек.

### 6.1 Профиль (общий): `OpWorkProfile`
- type: `PROJECT | SPECIALIST | EMPLOYER`
- userType: `JOB_SEEKER | EMPLOYER` (ADMIN не показывать)
- email, phone, website, location
- avatarUrl, coverImage

### 6.2 Соискатель: `OpWorkJobSeeker`
- Личные данные: firstName, lastName, middleName, birthDate, gender
- Профданные: currentPosition, currentCompany, summary
- Зарплата: expectedSalary, salaryCurrency
- Готовность: isOpenToWork, isOpenToRemote, isOpenToRelocation
- Предпочтения: preferredLocations
- Соцсети: linkedinUrl, githubUrl, portfolioUrl

### 6.3 Опыт: `OpWorkExperience`
- company, position, description
- startDate, endDate, isCurrent
- location, employmentType

### 6.4 Образование: `OpWorkEducation`
- institution, degree, fieldOfStudy
- startDate, endDate, isCurrent
- description, grade

### 6.5 Компания: `OpWorkEmployer`
- companyName (обязательное)
- industry, description, mission, culture
- foundedYear, headquarters
- logoUrl, coverImageUrl
- companyEmail, companyPhone, companyWebsite
- linkedinUrl, twitterUrl, facebookUrl

### 6.6 Вакансия: `OpWorkJob`
- title, description
- requirements, responsibilities
- employmentType, experienceLevel, department
- salaryMin, salaryMax, salaryCurrency
- location, isRemote
- status: `DRAFT | ACTIVE | PAUSED | CLOSED | ARCHIVED`
- publishedAt, expiresAt
- статистика: viewsCount, applicationsCount, savesCount

### 6.7 Отклик/заявка: `OpWorkApplication`
- coverLetter, resumeUrl, portfolioUrl
- status: `PENDING | REVIEWED | SHORTLISTED | INTERVIEW | OFFER | REJECTED | WITHDRAWN`
- statusNotes
- appliedAt, statusUpdatedAt

Ограничение UX:
- `WITHDRAWN` может ставить только соискатель.

### 6.8 Навыки и теги
- Навык: `OpWorkSkill` (name, type, category, icon)
- Навык соискателя: уровень, yearsOfExp, isPrimary, lastUsed
- Навык вакансии: isRequired, importance, minLevel
- Тег вакансии: name, color (HEX)

### 6.9 Нотификации
- type, title, message, data
- isRead, isArchived, readAt
- нотификации привязаны к активному профилю

## 7) Экранные требования

## 7.1 Лендинг (новый)
Нужно спроектировать публичный лендинг с блоками:
- Hero: ценностное предложение + CTA "Я соискатель" / "Я компания"
- Как это работает (2 потока)
- Преимущества платформы
- Примеры вакансий/резюме (демо-карточки)
- Блок доверия (метрики/логотипы/отзывы)
- FAQ
- Footer

Лендинг должен вести в регистрацию/логин и быть полностью адаптивным.

## 7.2 Авторизация/регистрация
- Двухколоночная композиция для desktop, одноэкранная для mobile.
- В форме регистрации: email, пароль, подтверждение, выбор профиля.
- Поле политики можно заложить как optional/скрываемое (для будущего legal-этапа).

## 7.3 Кабинет компании
- Список вакансий: фильтры слева, контент справа, сортировки сверху.
- Карточки вакансий: статус, зарплата, локация, ключевые навыки, счетчики.
- Создание/редактирование вакансии: пошаговая или секционная форма.
- Страница вакансии: контент + боковой блок статистики и статуса.
- Заявки: компактные карточки кандидатов + фильтры/сортировки.
- Деталь заявки: основная колонка + правая панель статуса/заметок.
- История статусов и заметок: кнопка рядом со статусом, открывает timeline.

## 7.4 Кабинет соискателя
- Профиль + резюме: большие формы + табличные секции (опыт, образование, навыки).
- Поиск вакансий: фильтры, список, просмотр детали, быстрый отклик.
- Мои отклики: список с фильтрами и деталью каждого отклика.

## 7.5 Глобальный поиск и нотификации
- Глобальный поиск всегда в хедере.
- Нотификации: dropdown + отдельный экран "Все уведомления".
- В dropdown должны быть быстрые действия: прочитано, архив, очистка.

## 7.6 Переписка/Приглашения/Дашборд (как рабочие)
- Переписка: чат-экран со списком диалогов, историей сообщений, композером.
- Приглашения: отдельный список, визуально отличать от обычных откликов.
- Дашборды: отдельные версии для компании и соискателя с ключевыми KPI.

## 8) UX-практики для job-платформ (внедрить в макет)

1. Ясные CTA первого шага: "Создать резюме" / "Создать вакансию".
2. Прозрачный статусный цикл: цветовые бейджи + текстовые подписи.
3. Двухуровневая фильтрация: быстрые фильтры + расширенные фильтры.
4. Sticky-элементы на длинных страницах: кнопка сохранения, панель статуса.
5. Сохранение черновиков форм (UX-паттерн, даже если пока без реализации).
6. Empty state с действием, а не только сообщением.
7. Предпросмотр перед публикацией вакансии/резюме.
8. Быстрые действия в списках: открыть, редактировать, архивировать, удалить.
9. Видимые системные фидбеки: success/error/toast/loading/skeleton.
10. Снижение когнитивной нагрузки: группировка полей по смыслу.
11. Понятные ограничения в формах: max-length, форматы, подсказки до ошибки.
12. Безопасные destructive-сценарии: confirm modal + понятный итоговый результат.

## 9) Адаптивность

Сделать минимум 3 брейкпоинта:
- Mobile: 360-767
- Tablet: 768-1199
- Desktop: 1200+

Требования:
- Все ключевые сценарии доступны на mobile без потери функционала.
- Таблицы в mobile превращать в карточки.
- Фильтры в mobile уводить в drawer/sheet.
- Хедер и навигация адаптируются в компактный формат.

## 10) Дизайн-система

### Цвета
- Нейтральная светлая база, 1 акцентный цвет бренда, 1 служебный цвет для статусов.
- Явные токены для success/warning/error/info.

### Типографика
- Иерархия заголовков H1-H6
- Текстовые стили: body, secondary, caption
- Высокая читаемость на мобильных экранах

### Компоненты
- Buttons, Inputs, Selects, DatePickers, Textareas
- Chips/Tags/Badges
- Cards, Tables, EmptyState, Pagination
- Modals, Drawers, Toasts
- Tabs, Breadcrumbs, Stepper
- Timeline (для истории статусов)

### Состояния компонентов
- default, hover, focus, active, disabled, loading, error, success

## 11) Контент и тон

- Язык интерфейса: русский.
- Тон: деловой, простой, без канцелярита.
- Микрокопирайтинг: короткие, однозначные формулировки действий.

Переименования, которые должны быть отражены:
- `Добавить` -> `Добавить вакансию`
- `Фильтр` -> `Фильтры вакансий`
- `Найти` (в вакансиях) -> `Найти вакансию`
- `Фильтры` (в откликах) -> `Фильтрация откликов`
- `Найти` (в откликах) -> `Найти отклики`
- `Фильтры` (в заявках) -> `Фильтры заявок`
- `Найти` (в заявках) -> `Найти заявку`

## 12) Ограничения и бизнес-правила для макета

1. Вакансия видна соискателям только если `status = ACTIVE`.
2. Резюме видимо компаниям только если `isOpenToWork = true`.
3. Один соискатель не может откликнуться на одну вакансию дважды.
4. В нотификациях должна быть логика разделения по активному профилю.
5. Нужен экран "все уведомления" (включая просмотренные и архивные).

## 15) Критерии приемки

1. Все пользовательские сценарии покрыты экранами без пробелов.
2. На каждом ключевом экране есть понятный следующий шаг.
3. Макет выдержан в минималистичном стиле и не перегружен.
4. Mobile-версии не урезают основной функционал.
5. Термины и статусы единообразны во всех разделах.
6. Визуально различимы состояния: пусто, загрузка, ошибка, успех.
